# One RTV — demo คลิกได้

**เปิดดูออนไลน์:** https://cmg-warehouse.github.io/one-rtv/ (ตัวอย่างระบบจริง: https://cmg-warehouse.github.io/one-rtv/#/login) · EN / TH สลับได้มุมขวาบน

One RTV คือ demo ของระบบติดตามงานคืนสินค้า (RTV) ที่ใช้เลข RTV เลขเดียวเป็นหัวเรื่องของงาน ให้ทุกฝ่าย (Brand, CS คลัง, ขนส่ง, SCDC, คลัง CMG, Admin CN) เห็นสถานะ ผู้ที่งานค้างอยู่ด้วย และเอกสารอ้างอิงทั้งหมดในที่เดียว ตั้งแต่เปิดคำสั่งจนออก CN

**ข้อจำกัดของ demo นี้:** ไม่มี backend ไม่มีระบบ login และไม่เชื่อมต่อ SAP / Sprint FC ข้อมูลทั้งหมดเป็นข้อมูลจำลองที่เก็บในเบราว์เซอร์ (localStorage) ใช้โดยผู้นำเสนอคนเดียวบนเบราว์เซอร์เดียว สลับบทบาทเองจากเมนูบนหัวหน้าจอ

## คำสั่งที่ใช้

```
npm install      # ติดตั้ง dependency (ครั้งแรก)
npm run dev      # รันเพื่อพัฒนา / นำเสนอ
npm test         # รัน unit test และ UI test (Vitest)
npm run build    # สร้างไฟล์ static ในโฟลเดอร์ dist/
```

ผล build อยู่ใน `dist/`: `index.html` ไฟล์เดียวที่รวม JS และ CSS ไว้ในตัว (self-contained) บวกไฟล์โลโก้สองไฟล์ `crl-logo.svg` และ `cmg-logo.png` ที่ต้องอยู่โฟลเดอร์เดียวกัน เปิด `dist/index.html` จากโฟลเดอร์ (file://) ได้โดยตรง หรือวางบน web server ภายในก็ได้ ฟอนต์ Kanit / Sarabun โหลดจาก Google Fonts เมื่อมีอินเทอร์เน็ต ถ้าออฟไลน์จะใช้ฟอนต์ของระบบแทน

## วิธีนำเสนอ

1. เริ่มที่ **Flow** (เมนู Flow) เพื่อให้เห็นภาพรวมว่าใครทำขั้นไหน ขั้นไหนข้ามได้
2. ต่อด้วย **Demo นำชม** (เมนู Demo นำชม หรือปุ่มในหน้าแรก) เลือกเรื่องที่ต้องการ แล้วกด "ถัดไป" ทีละขั้น ระบบจะสลับบทบาทและทำงานแทนให้
3. จบที่ **Dashboard** เพื่อดูว่างานค้างอยู่กับใครและช่วงไหนใช้เวลานาน

ถ้าต้องการเริ่มใหม่ กดปุ่ม **รีเซ็ตข้อมูล** บนหัวหน้าจอ จะล้างข้อมูลที่ทดลองทำและกลับไปใช้ข้อมูลตั้งต้น

## กฎของ flow อยู่ที่ไหน

กฎทั้งหมด (ขั้นไหนข้าม ใครทำขั้นไหนได้ แบบ CN เอกสารที่ต้องมี สถานะรอ) อยู่ในไฟล์เดียวคือ `src/domain/rules.ts` และมี unit test กำกับ ส่วนการเปลี่ยนสถานะอยู่ใน `src/domain/machine.ts`

## ชั้น `src/api` กับ REST API ของระบบจริง

หน้าจอทุกหน้าเรียกข้อมูลผ่าน `src/api` เท่านั้น และฟังก์ชันมีรูปร่างตรงกับ endpoint ที่ระบบจริงควรมี จึงใช้เป็นแนวทางตั้งต้นได้ แต่ยังไม่ใช่การสลับเป็น backend จริงโดยไม่แตะหน้าจอ (ดูหัวข้อถัดไป)

| ฟังก์ชันใน `src/api` | REST ที่แนะนำ |
|---|---|
| `listRtvs` | `GET /rtvs` |
| `getRtv` | `GET /rtvs/{id}` |
| `createRtv` | `POST /rtvs` |
| `act` | `POST /rtvs/{id}/actions` (body = action) |
| `searchByAnyNumber` | `GET /rtvs?q=` |
| `putRtv` | เฉพาะ demo (ย้อนกลับในทัวร์) ไม่มีในระบบจริง |
| `resetData` | เฉพาะ demo ไม่มีในระบบจริง |

## สิ่งที่ต้องย้ายไปฝั่ง server เมื่อทำระบบจริง

1. `role` / `actor` ต้องมาจากการยืนยันตัวตน (Entra ID) ห้ามให้ฝั่ง client เป็นผู้บอก
2. การบังคับกฎทั้งหมดใน `src/domain/machine.ts` ต้องรันฝั่ง server ส่วนสำเนาฝั่ง client มีไว้ให้หน้าจอตอบสนองทันทีเท่านั้น
3. หน้าจอเรียก `owner`, `holds`, `nextStep`, `requiredDocs` จาก `rules.ts` โดยตรง ต้องเลือกทางใดทางหนึ่ง: แยก rules เป็น shared package ที่ใช้ร่วมกันทั้งสองฝั่ง หรือให้ API ส่งค่าเหล่านี้กลับมาพร้อมข้อมูล RTV
4. การรีเฟรชหน้าจออัตโนมัติใช้ event `one-rtv:changed` ภายในหน้าเดียวกัน ต้องเปลี่ยนเป็น polling หรือ push channel
5. การแยกสิทธิ์ตาม Brand / ขนส่ง (`DEMO_BRAND_ID`, `carrierActor`) ทำเฉพาะที่หน้าจอใน demo ต้องกลายเป็นการตรวจสิทธิ์จริงฝั่ง server
6. `src/domain/types.ts` คือโมเดลข้อมูล ให้อ่านคู่กับหัวข้อ 10 ของสเปก

## ข้อจำกัดที่รู้อยู่ของ demo

- ธงกล่องขาดจากการนับกล่อง (ขั้น 5, 6, 8) เทียบกับจำนวนกล่องตามที่ Brand แจ้งไว้เสมอ การนับครบในขั้นถัดไปไม่ปลดธงเอง ต้องให้ CS ปิดธง
- ใน Demo นำชม ถ้าผู้นำเสนอแก้ RTV ของเรื่องนั้นเองด้วยมือ ระบบนับว่า "ขั้นนั้นเสร็จแล้ว"
- กด **รีเซ็ตข้อมูล** ก่อนนำเสนอทุกครั้ง เพราะ Demo ที่เริ่มใหม่ระหว่างทางทิ้ง RTV ที่ทำค้างไว้
- เรื่องที่ 2 (Consign) เปิดคำสั่งโดย **ไม่ใส่** RTV Note (ห้าง) โดยตั้งใจ เพื่อให้เห็นสถานะรอ RTV Note
